# Physical interface acceptance contract

This inventory describes the current source and the remaining acceptance work. It is not a declaration that VisiDock has achieved the requested whole-app standard. The objective is a coherent, detailed physical product: visual construction, spatial relationships, temporal choreography and input behavior at every level. A skill's examples or a component library are not the ceiling.

Scope was checked against `VaultScreen.kt`, `CaptureScreen.kt`, `CropScreen.kt`, `ReadingStage.kt`, `CardCase.kt`, `Motion.kt`, `PhysicalScene.kt` and `MaterialTexture.kt`. “Atomic” includes text, icons, indicators, image states, outlines, seams, handles, focus and error states—not only buttons. Android-owned permission dialogs, photo pickers, keyboard, contacts editor and external apps remain outside our rendering control; their app-side handoffs are included.

## Reading the inventory

- **S:** source implementation exists. This says nothing about the quality of the final rendered result.
- **P:** proposed or incomplete acceptance behavior. Do not report it as shipped.
- **T:** named test source covers some behavior; it is not a claim that the current build passed that test.
- **V:** current animation-enabled visual/device acceptance remains required.
- **N/A:** a physics effect is deliberately inappropriate, such as shifting selectable text while reading it.

Every row requires V unless explicitly an Android-owned surface. Earlier build/test results do not automatically validate the new material treatment. Build, test and visual results belong in `Verification.md` with the actual artifact/version.

## Global contract

Visual design establishes material, geometry, light and readable content. Motion establishes where an object belongs, what moves relative to it and what remains anchored. Animation describes the trajectory through time and its relationship to actual application state. Physics supplies continuous input, momentum and consistent material response. These four concerns must be evaluated independently; success in one does not imply the others.

1. **Identity:** a photograph/card retains its identity through capture, crop, scan, review, save, open and return. No unrelated duplicate card should appear to replace it during a handoff.
2. **Ownership:** each moving object has a source, destination and supporting plane. A sheet may rise from the bottom, but an object-specific action must retain visible context to the object it affects.
3. **Causality:** confirmation follows successful work. Loading is activity, not fabricated percentage. OCR regions must derive from recognized text. Editing remains possible when extraction is uncertain.
4. **Interruption:** new gestures start from the current rendered pose. Cancel does not commit. Retargeting does not reset to the beginning. Rapid actions neither duplicate callbacks nor strand an intermediate surface.
5. **Light:** upper-left light, navy contact/cast shadows, readable highlights. Shadow direction and support plane must remain coherent when an object rotates or lifts.
6. **Material:** leather has relief, compressed tooling, thread and edge thickness; paper has thin stacked edges; controls use consistent response categories. Texture never contaminates source photographs or OCR input.
7. **Restraint:** every unit has an intentional treatment; static text need not move forever. Frequent input stays immediate. Expressive journeys must not manufacture processing progress. The explicitly ordered scan sweep can hold an already-ready result until its finite presentation completes; it must not restart inference or conceal extra work.
8. **Accessibility:** reduced motion preserves state and direct manipulation. Keyboard, TalkBack, large text, focus, contrast and touch targets remain first-class. Color or motion alone cannot communicate success or failure.

## Atomic acceptance procedure

For each family, inspect rest, entry, pointer down, drag/hold where meaningful, release, canceled press, keyboard focus, accessibility activation, busy, success, error, retry, disabled, exit and reversal. A family may mark a state N/A with a reason; it cannot silently omit it.

For each scene, capture normal-speed video with Android animations enabled and a slow-motion frame sequence at handoff boundaries. Inspect shadow direction, silhouettes, object identity, z-order, clipping, typography, material scale and touches landing on the visible object. Test reduced motion separately; a reduced-motion recording cannot validate cinematic motion.

Measure responsiveness independently of appearance: immediate input acknowledgment, no full-size image decoding during drawing, bounded visible image work, no continuous composition caused solely by draw-phase pressure, and no animation-induced duplicate state changes. Record frame timing on the actual device rather than claiming smoothness from unit tests or a screenshot.

The current source is a foundation plus several authored scenes. The outstanding P entries above are part of the whole-app acceptance contract. They must remain visible until implemented and verified; neither a successful build nor a count of animated wrappers closes them.

## Control surface geometry correction

Decorated Material controls now disable Material's internal minimum-interaction layout reservation and reserve the 48dp interaction space outside their physical drawing. The fill, native border, clip, press outline and cast-shadow silhouette therefore use the same actual container dimensions. Caller-requested widths/heights remain effective. Shape parameters are explicit for pill buttons and chips; switches and navigation glyphs no longer receive an unrelated wrapper oval. Invisible edge targeting is exercised by `MotionInteractionTest.physicalButtonsPreserveRequestedSizesAndAccessibleTouchSpace`. This test source still requires device execution for the current build.

Camera toolbar and recovery panel now sit on a common lit supporting plane; the shutter's pressure closes its own metal contact shadow. Live camera framing is still a guide, not live boundary detection. These changes do not claim completion of all entries in the contract.
