## What is already in the attached project

The project is a native Android application written in Kotlin with Jetpack Compose. Its package/application ID is currently `io.caerulean.cardvault`. It uses Firebase Authentication with **email and password**, Cloud Firestore for card details, Firebase Storage for card images, and Google ML Kit’s on-device text recognition.

The main files are:

- `app/src/main/java/io/caerulean/cardvault/MainActivity.kt` — app screens and the current authentication, camera/import, OCR, Firebase, and contacts flows.
- `app/src/main/java/io/caerulean/cardvault/CardLogic.kt` — basic field extraction and search.
- `app/src/test/java/io/caerulean/cardvault/CardLogicTest.kt` — two small unit tests.
- `firestore.rules` and `storage.rules` — proposed per-user access rules.
- `README.md` — setup notes and current limitations.

The current flow is:

1. A user creates an email/password account or signs in.
2. They take a card photo using Android’s camera app or import an image.
3. ML Kit recognizes text on the device.
4. Simple heuristics suggest a name, job title, company, phone, email, and website.
5. The user reviews and edits fields, including address, notes, and the recognized text.
6. The app uploads a resized JPEG to Firebase Storage and stores the fields in Firestore under that user’s UID.
7. The home screen lists saved cards and searches their fields, notes, and OCR text.
8. Opening a card shows its details and saved image. The user can delete it.
9. “Add to phone contacts” opens Android’s contact editor with fields filled in; the user confirms Save in that app. The project does **not** directly write to Google Contacts or check duplicates.

The existing search is **keyword/phrase matching with a few synonyms and date filters**, not genuine AI semantic search. Examples like “this month” and “last month” have basic handling. It searches the records downloaded into the app.

The app currently disables Firestore disk persistence, blocks screenshots with `FLAG_SECURE`, and supplies Firebase rules intended to restrict each user to their own documents and images. These measures have **not** undergone a security review. Firebase provides its standard authentication, transport protection, and storage encryption; this is **not end-to-end encryption**.
